**1번 FinanceDataReader 원천·수정주가**

- 설치 버전 0.9.202. 소스 `FinanceDataReader/naver/data.py`를 읽어 기본 소스가 네이버 금융 차트 `https://fchart.stock.naver.com/sise.nhn?timeframe=day&count=6000&...`임을 확인. `KRX:` 접두사 소스는 "400 Bad Request (Period is up to 2 years)"로 1년 요청도 실패해 쓸 수 없음.
- 수정주가 여부는 문서에 없어 직접 확인: 삼성전자 2018-05-04 액면분할(50:1) 전인 2018-04-27 종가가 53,000원으로 나옴 → 분할 반영된 수정주가.
- 라이선스: GitHub API `/repos/financedata-org/FinanceDataReader/license` → MIT, `LICENSE.txt`, Copyright (c) 2024 FinanceData.KR. (처음에 `master/LICENSE` 경로로 받으려다 404. 파일명이 `LICENSE.txt`였음.)
- **원천 이용 조건 (문제 발견)**: `https://fchart.stock.naver.com/robots.txt`와 `https://finance.naver.com/robots.txt` 모두 `User-agent: * / Disallow: /`. 네이버 서비스 이용약관(시행 2026-10-01) 원문을 받아 보니 "자동화된 수단을 활용하는 등 … 비정상적으로 이용하여 게재된 게시물" 제한, "기술적 조치를 무력화하려는 일체의 행위" 금지, "네이버 서비스 또는 이에 포함된 소프트웨어를 복사·수정·판매·양도" 금지 조항은 있으나 시세 데이터 재이용에 대한 명시 조항은 없음. KRX 정보이용정책(코스콤 PDF)도 받아 읽었으나 이는 코스콤과 계약한 정보사업자·최종이용사 대상 문서라 개인의 웹사이트 조회에는 직접 적용되지 않음. → 서식4에 사실대로 적고, 공공데이터포털 대안은 사용자 결정으로 넘김.
- 라이브러리 라이선스 (GitHub API license 엔드포인트): DuckDB MIT, pandas BSD-3-Clause, Streamlit Apache-2.0.

**1번 지수 구성 종목**

- `fdr.SnapDataReader('KRX/INDEX/STOCK/1028')`(코스피200 구성)은 JSONDecodeError. KRX `getJsonData.cmd`를 직접 호출하니 응답이 "LOGOUT" → 세션 인증 필요. FDR 캐시 저장소(FinanceData/fdr_krx_data_cache)에도 1028·2203 구성 파일 없음.
- 대안으로 `fdr.StockListing('KRX')`(2,869종목, 시가총액 포함)에서 KOSPI 시총 상위 200 + KOSDAQ 시총 상위 150을 뽑음. 실제 지수 구성과 다를 수 있음을 spec에 명시.

**1번 거래세율 (법령 원문)**

- 법제처 API `https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&LM=증권거래세법시행령&type=XML`로 XML을 받아 조문 추출.
  - 증권거래세법 제8조: 기본세율 1만분의 35, 대통령령으로 인하 가능.
  - 증권거래세법 시행령(대통령령 제35947호, 시행 2026-01-02) 제5조: 본문이 "유가증권시장: 영(零). 다만 … 2024년 1만분의 3", "코스닥: 1만분의 15 … 2024년 1만분의 18"로 나옴.
  - 농어촌특별세법(시행 2026-05-12) 제5조 제1항 제5호: 증권시장 거래 증권 양도가액의 1만분의 15.
- **AI 답과 원문이 다른 점**: 웹 검색 요약은 "2026년 코스피 0.05%, 코스닥 0.20%"라 했는데, 법제처 API가 준 시행령 제5조 본문은 개정 전 문구(코스피 0, 코스닥 0.15%)였다. 2025-12-30 공포 개정령이 세율 조문을 바꿨다는 보도(한국세정신문 2025-12)와 공포번호 35947은 일치하나, API가 준 조문이 타법개정분이라 본문이 안 바뀌었을 가능성 있음. 2026년 세율은 조문 본문으로 재확인이 필요하다고 spec에 적음. 일단 v1 비용 가정은 코스피 0.05%+농특세 0.15%=0.20%, 코스닥 0.20%.
- 위탁수수료는 증권사 공식 공지를 못 찾아 0.015% 편도로 가정(비교 기사 기준, 출처 미확인). 슬리피지 0.1%는 근거 없는 가정.

### 프롬프트 2 (AI 내부 작업: "FinanceDataReader로 KRX 일봉 10년을 DuckDB에 넣는 스크립트")

`luckproof/data/fetch.py` 작성. 실행 `uv run python -m luckproof.data.fetch`. 355개 코드, 약 3분.

**어디서 깨졌고 무엇을 고쳤나**

1. 지수를 `KS11`, `KS200`, `KQ11`로 받으니(FDR이 야후로 보냄) 최신일이 2026-09-17에서 멈추고 ETF 캘린더 대비 13거래일 결측. 네이버 심볼 `NAVER:KOSPI`, `NAVER:KPI200`, `NAVER:KOSDAQ`으로 바꾸니 2,640행, 2026-10-12까지 결측 없음.
2. 두 번째 실행에서 지수가 안 바뀜. 원인: DuckDB에 이미 `prices` 테이블이 있으면 `CREATE OR REPLACE TABLE prices AS SELECT ... FROM prices`의 `prices`가 pandas DataFrame이 아니라 기존 테이블을 가리킴(테이블이 replacement scan보다 우선). 첫 실행 결과를 그대로 다시 쓰고 있었음. `con.register("df_prices", ...)`로 다른 이름을 붙여 해결. 이 버그는 출력 행 수가 같아서(799,236) 검증 쿼리로만 잡혔음.
