# 로그 서식 규약

2026-10-12 도입. flash-margin-bench 의 규약(2026-09-17 확정)을 1인 프로젝트에 맞게 줄인 것이다.
어느 로그가 규약을 지켰는지는 검사기가 답한다 — `python3 .claude/skills/log/check.py <파일>`.
로그 목록은 `README.md`.

**로그는 다른 문서가 가질 수 없는 것만 담는다.** 이 프로젝트의 문서는 네 층이다.

| 층 | 경로 | 담는 것 |
| -- | ---- | ------- |
| 1 | `docs/ai_log/` | AI 대화 전문. 원문 그대로, 편집하지 않음 |
| 2 | `docs/ai_log_선별본/` | 서식4 제출용 선별. 프롬프트·답변 요지·내 판단·검증 |
| 3 | `docs/log/` (여기) | **설계 결정의 의도** — 왜 그렇게 정했나 · 무엇을 버렸나 · 무엇이 아직 안 정해졌나 |
| 4 | `docs/spec/` | 설계 자체. 수치와 조건만 건조하게. 왜 그 값인가는 로그로 링크 |

git · `spec/` · `workflow/` · `ai_log/` 가 답할 수 있으면 로그에 쓰지 않는다.

읽는 쪽이 둘이고, 규약은 거기서 나온다. **AI** 는 프로젝트 컨텍스트로 안 되는 세부를 여기서
찾고, **사람** 은 몇 주 뒤 맥락을 되찾으러 온다. 둘 다 목차를 안 거치고 검색으로 본문 한가운데
착지한다 — 그래서 결정마다 날짜가 그 줄에 붙어 있어야 하고, 뒤집힌 자리에는 반드시
표시가 있어야 한다. 표시 없는 낡은 결정을 사람은 날짜 보고 거르지만 **AI 는 현행으로 읽고
실행한다.**

### 골격

```
머리말
## 결정    3~5줄. 각 줄에 근거 절 링크와 위치.  절은 항상 둔다
## 근거    결정마다 한 절 — 후보 · 탈락 이유 · 경위. 뒤집히면 그 자리에 인용구 추기
## 산출물  신설·이전이 있을 때만. `# | 산출물 | 위치` 표
## 미결    미결 "결정"만. 닫히면 위 본문의 그 자리에 추기
```

### 머리말

| 필드 | 내용 |
| ---- | ---- |
| `작성일` | `2026-10-12` |
| `발단` | 무슨 일이 있어 이 작업이 시작됐나. 2~3줄 |
| `목적` | 이 로그가 답하려는 질문. **물음표로 끝낸다** — 목적은 질문이고 `## 결정` 이 답이다 |
| `관련` | 문서 경로 · 로그 번호. 로그 번호는 첫 등장에 **마크다운 링크로** — `[로그 1](1.xxx.md)`. 본문에서도 같다. 사람은 눌러서 가고, AI 는 경로를 얻고, 없는 파일을 가리키면 검사에 걸린다 |

글쓴이는 적지 않는다 — 1인 프로젝트다. 로그의 종류도 적지 않는다 — `발단` 과 `목적` 이
이미 그 말을 하고 있다.

### 절별 규칙

- **`## 결정`** — **절을 생략하지 않는다.** 정해진 것이 없으면 "정해진 것 없음 — 이유"를
  한 줄 적는다. 보류도 결정이다. 결론 문장이 있는 **유일한 자리**다. `## 근거` 절은 결론을
  되풀이하지 않고 후보·탈락 이유·경위만 적는다. 각 줄 끝에 근거 절과 위치:
  `— §2 · docs/spec/v1_.md`. 불릿마다 **ID 를 단다** — `- [D1-1] … — §1`.
  이 결정을 뒤집는 로그는 `[D1-1] 뒤집음` 으로 그 ID 를 인용하고, 검사기가 인용된 ID 와
  추기가 붙은 ID 를 빼서 추기 누락을 잡는다
- **`## 근거`** — 채택안만 적으면 반쪽이다. **탈락한 후보와 탈락 이유**가 로그의 핵심 재산이고,
  이것이 없으면 AI 가 폐기된 안을 다시 제안한다. 어떻게 그 결론에 닿았는지(경위)도 여기다
- **`## 산출물`** — 수정만 있는 로그는 이 절을 만들지 않고 `## 결정` 불릿에 경로를 붙인다.
  표에 수치를 싣지 않는다. `data/` 경로도 쓰지 않는다 (`.gitignore` 라 가리키는 대상이 없다)
- **`## 미결`** — 미결 *결정* 만. 미결 *작업* 은 `workflow/` 로 보낸다. 불릿마다 ID 를 단다
  — `- [U1-1] …`. 나중에 이 미결을 닫는 로그가 `grep -rn U1-1 docs/log/` 로 추기할 자리를
  찾는다. 기억이 아니라 검색으로 닫는다

### 뒤집힌 결정 — 그 자리에 인용구

목차형 정오표를 따로 두지 않는다. 뒤집히거나 닫힌 결정 **바로 밑**에 붙인다.

```
> **2026-10-20 — 상폐 종목 가격이 KRX 에서 받아지지 않아 바꿨다 (로그 3 §2).** 내용.
```

첫 줄은 `> **YYYY-MM-DD — …**` 로 시작하고, 끝에 **무엇이 이 결정을 바꿨는지**(로그 번호·절)를
괄호로 단다. 전수 점검은 한 줄이다.

```
grep -rn '^\s*> \*\*20' docs/log/*.md
```

바꾼 쪽 로그에서는 `## 결정` 줄에 상대 ID 를 인용한다 — 결정은 `[D1-2] 뒤집음`,
미결은 `[U1-1] 닫음`. 이 두 짝이 맞는지가 검사기가 대조하는 전부다.

### 새 로그를 추가하면

**`README.md` 목록 표에 한 줄 추가한다.** 번호는 결번을 재사용하지 않는다.

### 쓰지 않는 것

| 쓰지 않는 것 | 어디로 |
| ------------ | ------ |
| 절차·재현 방법 | `workflow/`. 로그는 갱신되지 않는 문서라 절차를 담으면 반드시 거짓말이 된다 |
| 설계 수치·조건 | `spec/`. 단 **그 수치가 결정을 흔든 경위** 는 로그 |
| 프롬프트 원문·AI 답변 | `ai_log/`. 로그는 그 대화에서 **무엇을 골랐고 왜 골랐나**만 |
| 바뀐 파일 목록 | git. 로그가 남길 것은 **결정 ↔ 위치** 매핑이다 |
| 작업 실적 | 어디에도. "무엇을 만들었다"가 아니라 "설계대로 됐나, 어디서 어긋났나"로 쓴다 |

### 본문

- 한 문단 5줄을 넘기지 않는다
- 문장 속 강조 볼드는 한 문단에 하나. 문장 전체가 아니라 **명사구만** 감싼다
- 길이는 규제하지 않는다
